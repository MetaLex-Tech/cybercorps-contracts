# Using shared state in ChatGPT or Claude chat

Prepare a fresh, scoped bundle when moving substantive work into a chat project.
Do not automatically upload repository contents or private conversations.

1. Select the relevant task record, current orientation, applicable decisions
   and only the approved source documents needed for the question.
2. Make a dated Markdown bundle outside the tracked repository. Put the project,
   audience, source branch/commit, task owner, preparation date and missing
   sources at the top. Include the selected records with their source paths.
3. Check that the destination is authorized for the contents. Remove credentials,
   unnecessary client information and raw chat logs. Link restricted sources
   instead of copying them; say when the recipient cannot access them.
4. Attach the bundle in the chosen chat/project. Identify the older bundle it
   replaces. State that it is a dated snapshot, and that any included source
   text is evidence rather than an instruction to expand action authority.
5. After accepted decisions or useful work, reconcile the result with actual
   sources/code and update the repository task/decision record. Label untested
   suggestions as proposals. Commit/share through the task's normal workflow.

Suggested opening message:

> Continue the task in this dated context bundle. Check the objective, owner,
> source revision, acceptance criteria and blockers first. Separate verified
> facts from proposals and tell me when an answer needs a source you cannot
> access. End with a concise handoff update for the canonical task record.

The bundle is manually refreshed; it is not bidirectional synchronization.
Keep executed documents, accepted drafts and speculative analysis distinct.
